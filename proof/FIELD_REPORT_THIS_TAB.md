## 1. What "android.jar" is (the first question)

`android.jar` is the Android platform's **stub class library**. It contains the compiled
API surface of the OS — every `android.*` class (Activity, WebView, Context, ...) — with
method bodies stripped to `throw new RuntimeException("Stub!")`. It ships inside the
Android SDK at `platforms/android-34/android.jar`.

Why it is needed:
- `kotlinc` compiles *against* it. When your code says `class MainActivity : Activity()`,
  kotlinc must find `android.app.Activity` on the **classpath**. Without it, every
  `android.*` symbol is "unresolved reference" — which is exactly the flood of errors
  measured in §4.
- `d8` (the dexer) uses it as `--lib` to know the API surface it may reference.
- `aapt2 link` uses it as `-I` (include) to resolve framework resources.

It is NOT bundled into the APK. It is a compile-time reference only. The real classes
live on the phone's `/system/framework/framework.jar` at run time.

Measured on this box:
```
find / -name android.jar   ->  (none found)
```
So `build.sh` correctly refuses to run: `die "android-34 android.jar missing (set ANDROID_JAR)"`.
That guard is real and working (build.sh line 89).

## 5. The genuine build defect, proven by execution

`build.sh` step 5 re-packs the APK. Its code (line 171):
```python
with zipfile.ZipFile(base) as zin, zipfile.ZipFile(tmp,"w",zipfile.ZIP_DEFLATED) as zo:
    for e in zin.infolist():
        if e.filename=="classes.dex": continue
        zo.writestr(e.filename, zin.read(e.filename))
```
Running this exact logic on the real `base.apk` produced:
```
resources.arsc                    DEFLATED
lib/arm64-v8a/libaapt2.so         DEFLATED
lib/arm64-v8a/libzipalign.so      DEFLATED
```
So the repack DOES destroy STORED. The reason the shipped APK is fine is that it was
produced by a run whose repack preserved STORED (or a differently-ordered run); the
current `build.sh` would regress it. **Fixed**: the repack now forces STORED for
`resources.arsc` and `lib/*`; re-running the patched block yields STORED for all three.

# ADDENDUM — the real comment defect, located (2026-11-10)

The briefing named 19 files whose top comment block lost its `/*`. The character-level
scanner (`tools/syntax_gate.py`) was run over all three trees. Result:

```
tree        syntax_gate: PASS — 50 .kt files, every block comment closed.
tree.orig   syntax_gate: FAIL — 2 files   (CssLite.kt @3, SubstrateIngestor.kt @92)
tree_omega  syntax_gate: PASS — 55 .kt files, every block comment closed.
```

So the defect is real but narrower and different from the briefing:

1. **Not 19 files — 2.** Only `core/CssLite.kt` and `core/SubstrateIngestor.kt`.
2. **Not a missing opener — a mangled closer.** The opening `/*` is present and correct.
   The damage is the CLOSING `*/`, rewritten to `//`:
   - `CssLite.kt` line 8: `//` where the block should close.
   - `SubstrateIngestor.kt` line 97: `//` where the block should close.
   Every later `//`-comment and every `*/` inside the file then read as comment body,
   so the block never closes.
3. **Only in `tree.orig`** (the oldest backup, newest file 2026-11-10). Both `tree` and
   `tree_omega` are clean. The compile log that reported "Unclosed comment" at
   `CssLite.kt:357` and `SubstrateIngestor.kt:468` was run against `tree.orig`, not a
   stale log as first thought — the 356/467 line counts line up once the file is known.
4. `tree.orig/CssLite.kt` also carried a stray extra `}` at its end (a second blind-edit
   artifact).

**Fix applied (tree.orig only, bytes changed):**
- line 8 of `CssLite.kt`: `//` -> `*/`
- line 97 of `SubstrateIngestor.kt`: `//` -> `*/`
- deleted the stray `}` at `CssLite.kt:356`

After the fix both files are **byte-identical** to their `tree_omega` counterparts, and
`syntax_gate` passes all three trees. This is verified by `cmp`, not by eye.

**Why this matters for the AndroidX problem:** it is a *separate* problem. `android.jar`
absent from the classpath (see §4) is why 147 errors appeared; the two unclosed comments
are only 2 of those 147. Fixing the comments does not make the tree compile — the
classpath must also carry `android.jar`.
