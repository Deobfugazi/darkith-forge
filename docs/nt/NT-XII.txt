ln x − n ln b = 0 ⟺ b^n = x


The three legs are forced by which coordinate is absent:


Known Unknown Leg Operation

b,n x Fold x = b^n

n,x b Unfold base b = x^(1/n)

b,x n Unfold exponent n = ln x / ln b


The invariant: R∘F = π_b and L∘F = π_n. Rooting undoes the base; log-ing undoes the exponent. Nothing added; nothing lost.


The residual for any candidate triple is one scalar:


r = ln x − n ln b


On the relation, r = 0 exactly. Off the relation, r ≠ 0, and r's sign and magnitude measure the distance off the surface. The device is single-erasure-correcting and single-error-detecting: given two trusted coordinates, the third is repaired exactly; given no trusted pair, the error is detected but not localized. Redundancy is precisely 3-for-2. The device cannot silently lie.


The anchor pair: {0,1}. 1^n = 1 and ⁿ√1 = 1; 0^n = 0 and ⁿ√0 = 0 for n > 0. The identity row is b^0 = 1 ⟺ log_b(1) = 0: every orbit passes through (n=0, x=1). A collapse to 0 or 1, or a degenerate b=1 that refuses the log leg, is the signal that the process is stationary — change the frame, do not force the leg.


12.2 — The protocol


Applied by slot-counting, not operation-selection. The practitioner never asks is this a log problem or a root problem? — only which slot is empty?


Step 1 — Classify. Map the three quantities: rate/factor/base → b; count/scale/duration/dimension → n; total/result/outcome → x.


Step 2 — Identify the empty slot. The absent coordinate names the leg.


Step 3 — Apply the forced leg. Empty x → fold. Empty b → unfold base. Empty n → unfold exponent.


Step 4 — Certify. Push the answer back through a second leg; it must return an original input.


Step 5 — Anchor check. If the answer is 0 or 1, or if b=1, flag a fixed point.

13.5 — The Seven-Step Forced Chain


Step 1 — Compile resources


aapt2 compile --dir res -o compiled_res.zip


· Invariant: aapt2 is aarch64; resources are well-formed XML.

· Forced output: compiled_res.zip (.flat intermediates).

· Residual: XML syntax error naming the file and line.


Step 2 — Link resources + manifest


aapt2 link -o base.apk -I "$ANDROID_JAR" 

--manifest AndroidManifest.xml compiled_res.zip --java gen/


· Invariant: manifest references resolve; android.jar is loadable.

· Forced output: base.apk (unsigned resource APK) + gen/R.java.

· Residual: missing resource/manifest error, or failed to load include path (→ drop to API 34 — which is already the locked ceiling, so this should not fire).


Step 3 — Compile source


kotlinc src/ gen/R.java -classpath "$ANDROID_JAR" 

-J-Xmx512m -d classes/


· Invariant: classpath includes android.jar + gen/; kotlinc does not silently fail (jansi crash).

· Forced output: .class files in classes/.

· Residual: compile error naming file and symbol; or exit 0 with empty .class files (jansi crash — check stderr).

· 4GB note: -J-Xmx512m caps the JVM heap. If OOM persists at 512m, the Kotlin frame is broken on this device — switch to Java (javac).

· NEVER note: Do not add -include-runtime. The Kotlin stdlib is managed by kotlinc's own default classpath. Bundling it into classes.jar increases d8's memory pressure on a 4GB device.


Java path (alternative to step 3):


javac -source 8 -target 8 -classpath "$ANDROID_JAR" -d classes/ src/*.java gen/R.java


Step 4 — Dex


d8 --min-api "$MIN_SDK" --lib "$ANDROID_JAR" 

--output ./ $(find classes -name '*.class')


· Invariant: --lib android.jar present (required for Java 8+ features); --min-api matches the manifest's minSdk.

· Forced output: classes.dex.

· Residual: NoClassDefFoundError: android/... → missing --lib; unresolved type error names the class.


Step 5 — Package


rm -f base.apk classes.dex # clean base before re-packing

zip -j base.apk classes.dex


· Invariant: classes.dex at APK root; no duplicate entries; clean base.apk before packing.

· Forced output: unsigned APK (base.apk now contains resources + code).

· Residual: missing DEX or asset.


Step 6 — Align (MANDATORY)


command -v zipalign >/dev/null 2>&1 || { echo "ANCHOR: zipalign missing — alignment is a forced leg"; exit 1; }

zipalign -p 4 base.apk aligned.apk


· Invariant: zipalign present; uncompressed entries start at 4-byte multiples (-p 4 also page-aligns .so).

· Forced output: aligned.apk.

· Residual: zipalign absent → build stops; alignment verification fails → build stops.

· Alignment is not optional. An unaligned APK forces the Android runtime to copy uncompressed entries into RAM instead of mapping them, increasing resident memory on a 4GB device. The invariant build does not produce unaligned artifacts. There is no fallback. There is no cp base.apk aligned.apk. The signer never sees an unaligned APK.


Step 7 — Sign


[ -f debug.keystore ] || keytool -genkeypair -v -keystore debug.keystore 

-alias androiddebugkey -keyalg RSA -keysize 2048 -validity 10000 

-storepass android -keypass android 

-dname "CN=Android Debug,O=Android,C=US"

apksigner sign --ks debug.keystore --ks-key-alias androiddebugkey 

--ks-pass pass:android --key-pass pass:android 

--v2-signing-enabled true --out app-signed.apk aligned.apk


· Invariant: keystore exists; input is aligned.apk (not base.apk); v2 signing enabled (required for Android 7.0+).

· Forced output: app-signed.apk — installable artifact.

· Residual: No keyStore → missing keystore; tamper detection → nonzero exit.

· Signing an unaligned APK and then aligning it invalidates the signature. Order is forced: align → sign. The signer's input is aligned.apk. base.apk is never signed.
