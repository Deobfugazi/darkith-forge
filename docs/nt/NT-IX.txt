PART ZERO — THE ETYMOLOGICAL GROUND

0.1 — Resolver | RESOLVED (etymology), INFERRED (framing)

From Latin resolvere — "to loosen, untie, release" — from re- (back) + solvere (to loosen). The root is the loosening. A resolver does not create the answer. It unties the knot that held the unknown in place. The knot is the empty slot. The loosening is the forced leg.

0.2 — Triad | RESOLVED (etymology), INFERRED (use as a name)

From Greek trias — "a group of three" — from treis (three). The root is the three. The triad is not three facts. It is one fact with three faces. The faces are the same surface read from three directions.

0.3 — Slot | RESOLVED (etymology), INFERRED (use as a name)

From Old French esclot — "hollow of the breast, a groove" — possibly from Old Norse slóð — "a track, a trail." The root is the groove. A slot is the place where the missing coordinate sits, shaped to receive exactly one leg. The empty slot is the question. The leg is the forced answer.

0.4 — Residual | RESOLVED (etymology), EXPOSABLE (mathematical use)

From Latin residuum — "that which remains behind" — from residere (to remain, stay behind). The root is the remainder. A residual is what the relation leaves over when the candidate triple is placed against the constraint. If the remainder is zero, the triple is on the surface. If nonzero, the remainder is the measure of the distance off the surface.

0.5 — Anchor | RESOLVED (etymology), INFERRED (use as a name)

From Latin ancora — from Greek ankyra — "anchor." The root is the hook that holds the ship. An anchor is the fixed point against which motion is measured. The anchor pair {0,1} is the fixed set of the triad — the two constants that return themselves under both folding and unfolding.

0.6 — Noveltreatise | RESOLVED (etymology), INFERRED (definition)

Novellus (new shoot) + tractatus (a handling drawn out along a trace). A formal, systematic handling that draws out a trace of a new growth already running but not yet traced in this form.

0.7 — Autophagic | RESOLVED (etymology), INFERRED (use as a name)

From Greek autos (self) + phagein (to eat). The root is self-consumption. In this document's framing: the deletion of any file or script that requires Gradle, Maven, x86 binaries, or a compatibility patch to function. The self eats its own incompatible residue so the generative environment is not contaminated.

0.8 — Alignment | RESOLVED (etymology and operational definition)

From ad- (to) + linea (line). The root is the line — the shared boundary along which two edges meet without offset. In the APK container, alignment means the uncompressed data's byte offset is an exact multiple of the alignment stride (4 bytes; page-aligned for .so via -p). Alignment is not decoration and not optional: it is the condition under which the Android runtime may mmap() uncompressed entries directly. An unaligned entry cannot be mapped; it must be copied into RAM. On a 4GB device the copy is the hostage-taking. The invariant build therefore signs only aligned APKs.

PART TWO — THE OBJECT: THE CLOSED TRIPLE AND THE RESIDUAL | RESOLVED

For b > 0, b ≠ 1, n ∈ ℝ, define x = b^n. The triple (b,n,x) is a closed triple. Three coordinates, two degrees of freedom, one redundancy. The surface constraint is:

```
ln x − n ln b = 0   ⟺   b^n = x
```

The three legs are forced by which coordinate is absent:

Known Unknown Leg Operation
b,n x Fold x = b^n
n,x b Unfold base b = x^(1/n)
b,x n Unfold exponent n = ln x / ln b

The invariant: R∘F = π_b and L∘F = π_n. Rooting undoes the base; log-ing undoes the exponent. Nothing added; nothing lost.

The residual for any candidate triple is one scalar:

```
r = ln x − n ln b
```

On the relation, r = 0 exactly. Off the relation, r ≠ 0, and r's sign and magnitude measure the distance off the surface. The device is single-erasure-correcting and single-error-detecting: given two trusted coordinates, the third is repaired exactly; given no trusted pair, the error is detected but not localized. Redundancy is precisely 3-for-2. The device cannot silently lie.

The anchor pair: {0,1}. 1^n = 1 and ⁿ√1 = 1; 0^n = 0 and ⁿ√0 = 0 for n > 0. The identity row is b^0 = 1 ⟺ log_b(1) = 0: every orbit passes through (n=0, x=1). A collapse to 0 or 1, or a degenerate b=1 that refuses the log leg, is the signal that the process is stationary — change the frame, do not force the leg.

Demonstration 1 — The AI Coding Productivity Gap: The Exponent That Did Not Move | RESOLVED

The problem. AI coding agents are widely reported to make developers faster. The unresolved question is: faster at what, and does speed in code generation translate into speed in delivered software?

The live data. A Harvard working paper analyzed 718 firms and over 725,000 workers from 2021 to 2026. AI agents increased code production by 30% — adding nearly 1,500 lines per worker-month — while producing no statistically significant increase in resolved Jira issues or completed epics. Commits rose 20%; pull requests rose 23%; review times jumped 49%, increasing by an average of 3.45 days; the share of PRs requiring revision nearly doubled; comments per request rose 35%. Atlassian's 2026 survey found 87% of developers code faster with AI, but 72% report the same or greater friction across the lifecycle; the share reporting at least 10 hours saved weekly fell from 68% in 2025 to 25% in 2026.

Slot classification.

Slot Quantity Live value
b fold factor per unit of code produced falling (AI makes code cheap)
n judgment density per delivered outcome not falling (review, integration, accountability)
x delivered software value flat (resolved issues unchanged)

The empty slot. n. The forced leg is the log: n = ln x / ln b. If b falls but n does not, x does not rise proportionally. The 30% more code / 0% more resolved issues ratio is the residual r ≠ 0 — the measure of the gap between code generation and delivered value.

The certification. The device does not say AI is useless. It says the triple (b,n,x) for code production is on-surface (more code is produced), but the triple for software delivery has a different n — judgment density — and that n is the binding constraint. The 49% review-time increase is the physical manifestation of the unchanged n: more code enters the review queue, and the review queue is where judgment is applied. The bottleneck moved; the exponent did not.

Anchor check. No collapse to 0 or 1. The process is live. But the residual is the signal: the claim that AI accelerates software delivery is off-surface unless n is shown to fall. The live data show n is flat. The residual catches the lie.

Demonstration 2 — The Junior-Gap Paradox: The Exponent That Is Being Hollowed Out | EXPOSABLE

The problem. Entry-level software roles are the mechanism by which the n-slot — accumulated judgment — is replenished. If the n-slot is closed to new entrants, the system consumes its judgment stock without replacing it. The unresolved question is: what happens to the exponent when the apprenticeship ladder is removed?

The live data. Anthropic's junior technical hires fell from 27% to 9% of technical hiring; junior-level employees in technical departments slipped from 21% to 14% since early 2025. By August 2026, AI agents directed by employees were working six times as many hours as their human handlers. Code commits per engineer rose to five times their level six months earlier. A Harvard study of 62 million workers found junior developer employment drops by about 9–10% within six quarters of generative AI adoption. Meanwhile, employers increasingly prioritize "independent judgment, adaptability" over "narrow technical expertise."

Slot classification.

Slot Quantity Live value
b cost per syntactic artifact falling
n judgment capacity per worker not being replenished at entry level
x delivered reliability over career horizon future residual

The missing slot. The n-slot is not a number in a single triple. It is the stock that the triple draws on. The junior role is the b-work that silently accumulates n-capacity. AI automates the b-work, closing the entry point to n-accumulation. The triple closes for any single delivery, but the career-horizon triple — b = learning rate, n = years of apprenticeship, x = judgment capacity — has a nonzero residual: the n-slot is being depleted.

The certification. The device's verdict: you can replace a junior analyst with a tool. You cannot replace the five years of institutional knowledge that junior analyst was quietly accumulating. That knowledge walks out the door and does not come back. The 74.1% of AI-agent PRs merged with no changes at all — not reviewed and revised, merged unmodified — is the signal that the judgment layer is being bypassed, not augmented. Refactored code collapsed from 21% to 3.8% of all changes. Refactoring is the activity that turns generated code into understood code. It has nearly stopped.

Anchor check. No collapse to 0 or 1. But the residual is accumulating at the career horizon. The device detects it; it does not correct it.

Demonstration 3 — Token Economics: The Base Is Not Constant | RESOLVED

The problem. AI inference has non-zero marginal cost. The unresolved question is: what is the fold factor per unit of capability, and is it stable?

The live data. The cheapest small models from Anthropic and OpenAI bill $0.10 per million input tokens; frontier models bill $10 per million; output costs roughly five times the input rate. Claude Haiku 5.5 and GPT-6 Luna are the cheapest capable small models at $0.10 input / $0.50 output per million. The price range spans 100-fold across the model spectrum. Two of Google's current models are scheduled to double in price by January 1, 2027.

Slot classification.

Slot Quantity Live value
b fold factor per unit of capability falling for fixed capability
n capability per token rising (models get better per token)
x price per unit of delivered capability compressing

The missing slot. The base b is not constant. In 2023–2026, b for a fixed capability fell. But capability itself rose. The triad has two moving coordinates: b(t) falling for fixed capability; n(t) rising because capability per token is increasing. The residual against a constant b is nonzero. The device detects the price collapse; it does not certify a constant base. The correct frame is a time-varying triple, not a static one.

The certification. Token pricing is not a Wright's-law learning curve with a stable b. It is a triple with both b and n moving. Any forecast that assumes a fixed b will carry a nonzero residual. The 100-fold price range across model tiers is the structural signature of a non-constant base: the fold factor depends on which capability tier is selected.

Anchor check. No collapse. The process is live and the base is moving.

Slot classification.

Slot Quantity Live value
b fold factor per doubling 2

The 4.3-month figure is the forced log from the 130.8-day doubling; the 7-month figure is the forced log from the longer trend. Both are on-surface; neither is uniquely selected.

Anchor check. No collapse. The output is a bounded range, not a point.

PART SEVEN — LIMITATIONS AND FALSIFICATION | RESOLVED

Limitations.

1. The source data for the economic demonstrations are retrieved at the runtime instant, but the full uncertainty quantification of each source is not carried verbatim. The arithmetic is rewalkable; the confidence intervals are EXPOSABLE.
2. The cross-scale identification (that every prior NT tested the same triad) is the author's compression, marked INFERRED.
3. The resolver handles multiplicative/exponential structure. It does not handle additive structure. a+b=c is not a triad in this sense; it is a different object. The boundary is stated.
4. The residual detects and corrects a single untrusted coordinate only when two are designated as trusted. If no coordinate is trusted, the residual detects but does not localize. This is a feature, not a bug: the device refuses to guess.
5. In the compiler instantiation, the algebraic triple is a schema, not a numerical solver. The "residual" is the refinement/mismatch predicate, not literally ln x − n ln b. The structure — trusted pair → forced third → residual → certify → localize — is what transfers. That is division of labor, not a gap.
6. In the build instantiation, bash can detect the aapt2 API 35 fracture but cannot repair it. The anchor fires; the frame changes to 34. The script enforces the chosen frame; it does not change the frame.
7. The android.jar is the one unavoidable reference artifact. There is no substitute, and it is not a dependency resolver. It must be supplied manually from the official SDK repository or extracted from an existing SDK installation.
8. The alignment leg's memory benefit is stated qualitatively. The precise resident-memory delta on this specific 4GB device is EXPOSABLE; the rule (aligned input to the signer) is RESOLVED.

Falsification conditions.

· A triple satisfying b^n = x with independently measured b,n,x for which r ≠ 0.
· A triple with r = 0 that fails to reproduce x under the fold leg.
· A cross-scale application where the triad closes (r = 0) but the bond fails, or where the triad is off-surface (r ≠ 0) but the bond holds.
· A compiler fault that is localizable by the forced-leg structure but does not exhibit the trusted-pair → forced-third → residual shape.
· A Termux aapt2 build that loads android-35/android.jar without a patch, an external binary, or a frame change.
· An APK whose uncompressed entries are not 4-byte aligned and which nevertheless achieves direct mmap() access of those entries on Android without a copy.

None has been found. The synthesis makes the triad a testable hypothesis at every scale.

9.5 — The Seven-Step Forced Chain

Step 1 — Compile resources

```bash
aapt2 compile --dir res -o compiled_res.zip
```

· Invariant: aapt2 is aarch64; resources are well-formed XML.
· Forced output: compiled_res.zip (.flat intermediates).
· Residual: XML syntax error naming the file and line.

Step 2 — Link resources + manifest

```bash
aapt2 link -o base.apk -I "$ANDROID_JAR" \
  --manifest AndroidManifest.xml compiled_res.zip --java gen/
```

· Invariant: manifest references resolve; android.jar is loadable.
· Forced output: base.apk (unsigned resource APK) + gen/R.java.
· Residual: missing resource/manifest error, or failed to load include path (→ drop to API 34 — which is already the locked ceiling, so this should not fire).

Step 3 — Compile source

```bash
kotlinc src/ gen/R.java -classpath "$ANDROID_JAR" \
  -J-Xmx512m -d classes/
```

· Invariant: classpath includes android.jar + gen/; kotlinc does not silently fail (jansi crash).
· Forced output: .class files in classes/.
· Residual: compile error naming file and symbol; or exit 0 with empty .class files (jansi crash — check stderr).
· 4GB note: -J-Xmx512m caps the JVM heap. If OOM persists at 512m, the Kotlin frame is broken on this device — switch to Java (javac).
· NEVER note: Do not add -include-runtime. The Kotlin stdlib is managed by kotlinc's own default classpath. Bundling it into classes.jar increases d8's memory pressure on a 4GB device.

Java path (alternative to step 3):

```bash
javac -source 8 -target 8 -classpath "$ANDROID_JAR" -d classes/ src/*.java gen/R.java
```

Step 4 — Dex

```bash
d8 --min-api "$MIN_SDK" --lib "$ANDROID_JAR" \
  --output ./ $(find classes -name '*.class')
```

· Invariant: --lib android.jar present (required for Java 8+ features); --min-api matches the manifest's minSdk.
· Forced output: classes.dex.
· Residual: NoClassDefFoundError: android/... → missing --lib; unresolved type error names the class.

Step 5 — Package

```bash
rm -f base.apk classes.dex   # clean base before re-packing
zip -j base.apk classes.dex
```

· Invariant: classes.dex at APK root; no duplicate entries; clean base.apk before packing.
· Forced output: unsigned APK (base.apk now contains resources + code).
· Residual: missing DEX or asset.

Step 6 — Align (MANDATORY)

```bash
command -v zipalign >/dev/null 2>&1 || { echo "ANCHOR: zipalign missing — alignment is a forced leg"; exit 1; }
zipalign -p 4 base.apk aligned.apk
```

· Invariant: zipalign present; uncompressed entries start at 4-byte multiples (-p 4 also page-aligns .so).
· Forced output: aligned.apk.
· Residual: zipalign absent → build stops; alignment verification fails → build stops.
· Alignment is not optional. An unaligned APK forces the Android runtime to copy uncompressed entries into RAM instead of mapping them, increasing resident memory on a 4GB device. The invariant build does not produce unaligned artifacts. There is no fallback. There is no cp base.apk aligned.apk. The signer never sees an unaligned APK.

Step 7 — Sign

```bash
[ -f debug.keystore ] || keytool -genkeypair -v -keystore debug.keystore \
  -alias androiddebugkey -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass android -keypass android \
  -dname "CN=Android Debug,O=Android,C=US"
apksigner sign --ks debug.keystore --ks-key-alias androiddebugkey \
  --ks-pass pass:android --key-pass pass:android \
  --v2-signing-enabled true --out app-signed.apk aligned.apk
```

· Invariant: keystore exists; input is aligned.apk (not base.apk); v2 signing enabled (required for Android 7.0+).
· Forced output: app-signed.apk — installable artifact.
· Residual: No keyStore → missing keystore; tamper detection → nonzero exit.
· Signing an unaligned APK and then aligning it invalidates the signature. Order is forced: align → sign. The signer's input is aligned.apk. base.apk is never signed.
