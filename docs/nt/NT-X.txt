PART THREE — THE AUTOPHAGIC MEMORY BUDGET ALLOCATOR (THE MATH)

The allocator is a closed-loop PID controller that runs at every frame boundary. It consumes the system state and outputs three coupled scalars: vertex_budget, concurrency, and resolution_scale. It eats its own past allocation (autophagic) and re-derives the next budget from the measured residual.

3.1 The State Vector

At frame k, define the measured state:
x_k = [ T_k, G_k, C_k, H_k, M_k ]^T

Where:

· T_k = measured frame time (ms).
· G_k = GPU utilization ratio (0.0 to 1.0).
· C_k = CPU utilization ratio (max of the 8 cores).
· H_k = heap pressure ratio: (JavaHeapUsed + NativeHeapUsed) / DalvikHeapLimit.
· M_k = system memory pressure from lmkd (0.0 to 1.0).

3.2 The Control Vector

· r_k = dynamic resolution scale (0.3 to 1.0). The backbuffer is 1600 * r × 720 * r.
· s_k = splat/polyvertex budget (0 to N_max).
· p_k = heap reservation for the renderer (MB).

3.3 The Objective Function (Lyapunov Stability)

The goal is to maximize fidelity while guaranteeing T_k ≤ T_target. Define the Lyapunov candidate function:
V_k = (1/2) e_k^2 + (1/2) λ_1 (1 - r_k)^2 + (1/2) λ_2 (1 - s_k/N_max)^2

Where:

· e_k = T_k - T_target is the frame-time error.
· λ_1 = 10 (resolution restoration weight).
· λ_2 = 1 (splat restoration weight).

The allocator is stable if ΔV_k = V_{k+1} - V_k < 0.

3.4 The Control Law (The Derivation)

The frame time is modeled as:
T_k = (W_frag / (f_GPU * r_k^2)) + (W_vertex / (f_CPU * s_k)) + T_overhead

Taking the partial derivative with respect to r_k:
∂T_k / ∂r_k = -(2 W_frag) / (f_GPU * r_k^3)

For Lyapunov stability, we choose the control update:
r_{k+1} = r_k + η_r [ (2 W_frag e_k) / (f_GPU r_k^3) + λ_1 (1 - r_k) ]

Where η_r = 0.05 (stable for L ≈ 10). If e_k > 0 (slow), the brake term dominates and r decreases. If e_k < 0 (fast), the restore term pulls r back to 1.0.

3.6 The Vertex Budget Controller (PID Form)

Let V_k be the vertex budget at frame k. The controller is a discrete PID with anti-windup:
V_{k+1} = clamp( V_k + K_p e_k + K_i Σ_{j=0}^{k} e_j Δt + K_d (e_k - e_{k-1})/Δt, V_min, V_max )

Where:

· e_k = M_budget - M_gpu(V_k)
· K_p = 0.12 (1 MB over-budget → 120k vertex reduction)
· K_i = 0.004 (integral corrects slow drift)
· K_d = 0.08 (damps oscillation from the 820 MHz GPU clock)
· V_min = 65,536 (minimum viable set for 1600×720)
· V_max = 524,288 (ceiling derived from Mali-G52 MC2 ALU throughput)

Anti-windup: if V_{k+1} hits V_min or V_max, the integral term is frozen for that frame.

3.7 The Resolution Scaling (Mali-G52 MMU Hook)

The resolution scale is driven by the vertex-budget residual and the frame-time residual:
s_{k+1} = clamp( s_k * (1 - λ * (r_M / M_budget) - μ * (max(0, f_frame - 16.6) / 16.6)), 0.5, 1.0 )

Where:

· λ = 0.25 (memory-pressure scale factor).
· μ = 0.40 (frame-time scale factor).
· s_k ∈ [0.5, 1.0].

When the GPU is over-budget or the frame time is over 16.6 ms, the scale drops. When both residuals are zero, the scale recovers toward 1.0. The scale is applied to the vertex-shader's output resolution via the glViewport call before the draw.

package com.darkith.transliaison.core

import android.app.ActivityManager
import android.content.Context

class AutophagicAllocator(
    private val totalRamBytes: Long = 3_660_000_000L, // from sysinfo dump
    private val alpha: Double = 0.45,
    private val beta: Double = 0.08,
    private val gamma: Double = 0.15,
    private val lambda: Double = 0.25,
    private val mu: Double = 0.40
) {
    private var V_k = 262_144.0 // initial vertex budget
    private var s_k = 1.0       // initial resolution scale
    private var integral = 0.0
    private var lastError = 0.0
    private var lastTs = System.nanoTime()

    fun tick(
        freeRamBytes: Long,
        gpuMemBytes: Long,
        cpuLoad: Double,   // 0.0 .. 1.0
        frameMs: Double
    ): Allocation {
        val dt = (System.nanoTime() - lastTs) / 1e9
        lastTs = System.nanoTime()

        val mBudget = alpha * freeRamBytes * (1.0 - beta * cpuLoad)
        val error = mBudget - gpuMemBytes
        integral += error * dt

        // PID with anti-windup
        val p = 0.12 * error
        val i = 0.004 * integral
        val d = 0.08 * (error - lastError) / dt
        var V_next = V_k + p + i + d
        if (V_next <= 65_536.0 || V_next >= 524_288.0) integral = 0.0 // freeze
        V_next = V_next.coerceIn(65_536.0, 524_288.0)
        V_k = V_next
        lastError = error

        // GPU concurrency
        val cGpu = (8.0 * (1.0 - cpuLoad) / (1.0 + gamma * maxOf(0.0, frameMs - 16.6)))
            .toInt().coerceIn(1, 8)

        // Dynamic resolution scaling
        val memPressure = error / mBudget
        val framePressure = maxOf(0.0, frameMs - 16.6) / 16.6
        var s_next = s_k * (1.0 - lambda * memPressure - mu * framePressure)
        s_next = s_next.coerceIn(0.5, 1.0)
        s_k = s_next

        return Allocation(
            vertexBudget = V_k.toLong(),
            gpuConcurrency = cGpu,
            resolutionScale = s_k,
            memoryResidual = error,
            budgetCeiling = mBudget
        )
    }
}
